## Approach

The audit engine resolves request emails against current and historical identity records, parses participant-facing JSON and SQL evidence, extracts resource-linked text where possible, applies the supplied category action table, and serializes ordered operations. It excludes evidence later than `audit_at` and does not use `reported_status` to decide deletion state.

## Failures, limitations, and improvements

Iterative sample checks found and fixed incorrect resource parsing for system names, trace-level identity fields split across log lines, text extraction from compressed PDF streams, Portuguese deletion-intent vocabulary, and the important distinction between evidence capture time and event time. The implementation also clears evidence identifiers from all proposed post-remediation verification steps, recognizes explicit 404 profile lookups as absence, and validates every serialized step.

Evidence image files are not OCR-parsed by the standard-library implementation. PDF text extraction is best-effort and does not reliably decode every font encoding. Activity records are treated as claims and are not yet used as conclusive record-state proof. Where no matched evidence establishes a state, the engine returns `INCOMPLETE` with an explicit limitation rather than claiming absence. Remaining sample mismatches above are reported as measured; no score is inferred from output validity.

No hidden answers, organizer-only files, or generator internals were used.
